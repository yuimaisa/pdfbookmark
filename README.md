# pdfbookmark

書籍PDFの目次テキスト・画像をDeepSeekで構造化し、本文見出しと照合して階層付きブックマークを生成するローカルWebアプリです。日本語UI、500〜1000ページ程度の教科書・専門書を想定しています。初期設定は **DeepSeek / `deepseek-flash`** です。

## セットアップ・起動

[pixi](https://pixi.sh/latest/installation/) **0.84.1以上**をインストールし、リポジトリのルートで実行します。Pythonと依存パッケージはpixiが用意するため、事前のPythonインストールや仮想環境の有効化は不要です。既定環境はPython **3.12**です。

```bash
pixi install --locked
# 初回のみ。既存の .env がある場合はコピーせず、下記の設定を追記
cp .env.example .env
# .env の DEEPSEEK_API_KEY を設定してから起動
pixi run start
```

Windows PowerShellでは、設定ファイルのコピーに `Copy-Item .env.example .env` を使います。インストール・起動コマンドは共通です。Linux、macOS（Apple Silicon / Intel）、Windowsの環境をロックしています。

依存関係は `pyproject.toml`、解決済みのバージョンは `pixi.lock` で管理します。両方をGitに含め、依存関係を変更した場合は `pixi lock` でロックファイルを更新してください。環境は `.pixi/` に作成され、Git管理外です。従来の `.venv` を有効化している場合は `deactivate` してからpixiに切り替えてください。

ブラウザで <http://127.0.0.1:8501> を開きます。初期設定はローカル接続のみです。APIの利用料が発生します。

### ローカルOCRのセットアップ

画像PDFでは、日本語・英語をCPUで認識する次の環境を使います。テキストPDFだけなら上記の既定環境で利用できます。

```bash
pixi install --locked -e ocr
pixi run -e ocr ocr-setup
pixi run -e ocr start
```

`ocr-setup` は公式 [tessdata_fast](https://github.com/tesseract-ocr/tessdata_fast) の固定リビジョンから `jpn` / `eng`（計約4 MB）を取得します。初回の取得後は本文OCRにネットワーク接続は不要です。言語データの内容ハッシュとTesseractバージョンをキャッシュキーに含めます。

PP-OCRv6 mediumを使う場合は、独立したPaddle環境で起動し、画面のOCRエンジンを切り替えます。

```bash
pixi install --locked -e paddle
pixi run -e paddle start
```

PaddleOCR **3.7.0** / PaddlePaddle **3.3.1** / Python **3.12** を固定しています。公式の `PP-OCRv6_medium_det` / `PP-OCRv6_medium_rec` を明示指定し、日本語を含む多言語モデルを使います。[公式設定](https://github.com/PaddlePaddle/PaddleX/blob/release/3.7/paddlex/configs/pipelines/OCR.yaml)・[日本語対応のモデル選択](https://github.com/PaddlePaddle/PaddleOCR/blob/release/3.7/paddleocr/_pipelines/ocr.py)

Paddleのモデルは初回に公式配布先（Hugging Face / AI Studio / ModelScope / BOS）から取得されます。既定の保存先は `~/.paddlex/`、変更する場合は起動前に `PADDLE_PDX_CACHE_HOME` を指定してください。起動時にモデルファイルの内容ハッシュを計算するため、同名モデルの更新も古いOCRキャッシュと混同しません。画像の変形補正は使わず、入力画像とOCR座標の対応を維持します。

| 環境 | Python | OS・アーキテクチャ | 検証状況 |
| --- | --- | --- | --- |
| default / py311 / py313 | 3.12 / 3.11 / 3.13 | Linux x86_64・aarch64、macOS ARM・Intel、Windows x64 | 依存解決済み。今回のローカルテストはLinux x86_64 |
| ocr（Tesseract CPU） | 3.12 | 同上の5プラットフォーム | Linux x86_64で実OCR確認。各OS・ARMの実OCRは専用CIジョブで検証 |
| paddle（PP-OCRv6 medium CPU） | 3.12 | Linux x86_64、macOS ARM、Windows x64 | 依存解決済み。Linuxでインポート確認。今回の環境ではモデル配布先が403となり実認識は未検証 |

PaddlePaddle 3.3.1のPyPI配布にLinux aarch64・macOS Intelのwheelがないため、その2環境では動作する代替バックエンドとしてTesseractを使用します。`linux-aarch64` はpixiの依存解決とネイティブARM CIを追加していますが、x86_64上の確認をARM実機検証として扱いません。

GPUの選択肢はPaddleの `gpu:0` へ渡します。ロック済みのPaddle環境はCPU版であり、GPUを使うには対応するCUDA版PaddlePaddleとドライバーが必要です。CPU版でGPUを指定すると開始前にエラーにします。PyPIの `paddlepaddle-gpu` は現時点で2.6.2のため、3.3.1 CPU版と単純に置き換えることはできません。このPRではGPU環境を提供・検証していません。GPUが必要な場合は[公式インストール案内](https://www.paddlepaddle.org.cn/install/quick)の対応バージョンをpixi featureで管理してください。

### DeepSeek APIキーの設定

用意した **DeepSeekのAPIキー** を、リポジトリ直下の `.env` に設定します。APIキーはチャットやREADMEに貼らず、このローカルファイルにだけ記入してください。

```dotenv
DEEPSEEK_API_KEY=your-deepseek-api-key
DEEPSEEK_MODEL=deepseek-flash
```

`your-deepseek-api-key` を実際のキーに置き換えます。キーの管理と残高の確認は [DeepSeek Platform](https://platform.deepseek.com/) から行えます。`.env` はGit管理外です。設定変更後はStreamlitを停止し、再起動してください。環境変数として設定済みの値は `.env` より優先されます。

ファイルに保存せず使う場合は、画面左側の **LLMプロバイダーをDeepSeek** にして、「DeepSeek APIキー」欄に入力します。画面の入力値は、そのセッションで `.env` / 環境変数の値より優先されます。

- 初期モデル：`deepseek-flash`（画像入力も対応）。別の対応モデルを使う場合は `DEEPSEEK_MODEL` または画面の「モデル」を変更します。
- 接続先：`https://api.deepseek.com`。DeepSeekを選択している間、目次はDeepSeekへ送信します。
- 解析方式：JSON出力モード（`json_object`）。項目の型・必須フィールド・階層は、返答を受け取った後にPydanticでも検証します。
- 推論モード：費用・待ち時間を抑えるため無効。出力上限は16,000トークンです。

依存関係の `openai` は、DeepSeekのOpenAI互換APIを呼ぶためのPython SDKとしても使用します。DeepSeekの選択時はDeepSeekのキーと接続先を使用し、OpenAIのAPIキーは不要です。[DeepSeekのAPI仕様](https://api-docs.deepseek.com/)・[JSON出力仕様](https://api-docs.deepseek.com/guides/json_mode/)・[モデルと料金](https://api-docs.deepseek.com/quick_start/pricing/)

OpenAIを使う場合は画面のプロバイダーを明示的に切り替え、`OPENAI_API_KEY` / `OPENAI_MODEL` を設定します。OpenAI側はStructured Outputs対応モデルが必要です。両プロバイダーのキーとモデル設定は分離しています。

APIキーなしでも「500ページのサンプルPDFで試す」→「サンプル目次を読み込む（API不要）」から、照合・編集・PDF生成を試せます。サンプルの目次は英語ですが、アプリと見出し照合は日本語にも対応します。

## 使い方

1. PDFを読み込みます。画像だけのPDF・既存のテキストPDFを使用できます。ページ数、テキストを含むページ数、既存ブックマーク数を表示します。パスワード保護されたPDFは事前に解除してください。
2. 目次の開始・終了PDFページを指定し、「この範囲の目次テキストを抽出」を押します。必要に応じてプレビューし、抽出テキストを修正します。**画面上のPDFページ番号はすべて1始まり**です。
3. 目次解析の入力で「画像」または「テキスト」を選び、「LLMで目次を解析」を押します。画像モードはDeepSeek限定です。選択した目次ページのみをPyMuPDFでPNGに描画し、Base64 data URLとしてChat Completionsのuserメッセージに送ります。本文画像は送りません。画像は最大12ページ、幅最大1600 px（描画倍率上限2倍）、Base64合計24 MiBまでです。文字が小さい目次は範囲を分けて確認してください。[公式Vision仕様](https://api-docs.deepseek.com/guides/vision/)に従い、JSON出力とPydantic検証を使用します。解析・目次JSON読込は既存の編集結果を置き換えます。
4. 本文先頭の対応が分かる場合は「本文先頭のページ対応を使う」を有効にし、PDFページとその印刷ページ番号を入力して「ページ対応の設定を反映」を押します。例えば印刷1ページがPDF12ページ目なら、同じ番号体系の目次ページに11を足して推定できます。「本文先頭の画像を確認」で基準を確認できます。画像PDFではOCRエンジン・解像度・実行モードを選び、「OCRを実行・再開」を押します。OCR完了時に自動照合します。テキストPDFや再照合では「自動ページ照合を実行」を押します。本文テキストをローカル検索し、根拠・候補・ページ対応区間・不連続を表示します。基準の変更・解除時は自動結果と生成済みPDFを解除するので、再照合してください。手動指定した移動先は保持します。
5. 結果を表で編集し、**「編集内容を保存」**を押します。階層、見出し、印刷ページ、PDFページを変更でき、末尾で追加、行選択で削除できます。「未解決のみ」「要確認のみ」の絞り込み中も、他の行は保持されます。追加行は末尾に入ります。
6. 各項目の根拠・候補と対象ページのプレビューを確認します。OCRした行・信頼度・PDF座標を画像と比較できます。未解決項目は「未解決項目を再解析」で未処理ページを全文検索し、必要なら解像度を変更してOCRし直します。PDFページを変更した項目は手動指定として保持され、再照合時に保持するか選べます。自動判定された見出し・印刷ページを変更すると移動先を解除するので、再照合または手動指定してください。
7. 未解決項目を修正・削除し、「ブックマーク付きPDFを生成」を押してダウンロードします。既存ブックマークがある場合、出力側で置き換えるチェックが必要です。保存後にPDFを開き直し、全項目の数・階層・移動先を検証します。

階層は1から始め、深くするときは1段ずつ指定します。同じPDFページに複数項目を置けます。自動結果がすべて確定していれば、そのままPDFを生成できます。元のPDFのバイト列、ページ内容、画像は変更しません。出力には元のPDFが保持する注釈・メタデータも含まれます。

## 全文OCR・高速モード・再開

- **高速（既定）**：冒頭と中盤・終盤をサンプリングし、上部・下部の印刷ページラベルから区間別のページ対応を推定します。候補の前後2ページ、前後12ページの順にOCRし、未解決またはページ推定だけの項目が残れば全文OCRに移行します。ラベルだけではVerifiedにしません。
- **全文OCR**：目次も含め、文字情報のない全ページを順番にOCRします。テキストレイヤーがあるページは従来の抽出経路を利用します。
- 一度に保持する描画画像は1ページです。既定200 dpi、上限2500万画素で巨大なページのメモリを抑えます。3ページごとにStreamlitへ制御を戻し、進捗・完了・失敗・キャッシュ再利用数を表示します。中断操作は処理中のバッチの境界で反映されます。
- 「OCRを中断」後は「OCRを実行・再開」で続行できます。再起動した場合も同じPDF・設定で開始すると成功ページをディスクから再利用します。空白ページも成功として記録します。「失敗ページのみ再処理」はそのページだけを対象にします。編集やプレビューだけではOCRを実行しません。
- キャッシュは `~/.cache/pdfbookmark/ocr.sqlite3` にOCRテキスト・行座標・信頼度を保存します。`PDFBOOKMARK_CACHE_DIR` で保存ディレクトリを変更できます。PDFのSHA-256、ページ番号、エンジン、モデル・実行ライブラリのバージョン、DPI、画像上限、前処理をキーにします。各ページを独立してコミットし、中断済み・失敗ページは次回に再処理します。
- キャッシュは書籍のテキストを含みます。削除する場合はアプリを停止し、上記の `ocr.sqlite3` を削除してください。PDF画像・APIキーはキャッシュに含みません。編集したブックマークは従来どおり中間JSONへ保存してください。

## 検証状態と照合方法

| 状態 | 根拠 | 確認の目安 |
| --- | --- | --- |
| Verified | 独立した本文見出しの完全一致・正規化一致などが強く、重複や順序矛盾がない | 必要に応じてプレビュー |
| Probable | 曖昧一致・重複候補がページ対応と整合、またはユーザーの手動指定 | プレビューを推奨 |
| Estimated | 手動指定の基準、または複数のアンカーによるページ対応のみで推定 | 本文見出しの裏付けはないため要確認 |
| Unresolved | 根拠不足、重複、順序矛盾、オフセット変化の境界など | 手動指定または削除が必要 |

OCR由来のVerifiedには、強い本文見出し一致・OCR信頼度90%以上・目次順序に加え、印刷ページとの対応一致が必要です。ページラベルや手動基準だけの場合はEstimatedです。信頼度は確率ではなく、照合方法に基づくスコアです。手動指定は本文検証の完了を意味しないため、Verifiedにはしません。

処理は次の2段階です。

- **見出し検索**：全ページのテキスト・行／ブロック位置・文字サイズを一度抽出。NFKC、空白・記号・章節番号を検索用に正規化し、原文を保持します。文字n-gram索引で候補を絞り、完全一致・本文一致・RapidFuzzの曖昧一致、章節番号、ページ内の位置、文字サイズを評価します。最大3行の折返し見出しに対応します。OCR行ではピクセル座標を実際の描画寸法からPDF座標に変換し、bbox高さの相対差と行間による独立性を評価します（フォントサイズには変換しません）。認識信頼度の低い行を減点します。指定した目次ページを除外し、繰返しの柱・フッター、参照表現や目次らしい行を減点します。
- **ページ対応**：高信頼度・重複なしの見出しから目次順に単調なアンカー列を選び、アラビア数字・ローマ数字・付録番号を別体系として扱います。自動検出だけの場合は、異なる印刷ページのアンカーが少なくとも2件、同じオフセットを支持した場合に推定に使います。本文先頭のページ対応を手動指定した場合は、その1組からも推定できます。基準の印刷ページは数字・ローマ数字・付録番号（例：1、i、A-1）に対応し、別の番号体系には適用しません。区間ごとに異なるオフセットを認め、切替位置が未確定の区間や、矛盾する孤立アンカーを越えた外挿では数値だけの推定を避けます。強い本文一致は暫定オフセットより優先します。

この設計により、単一の誤一致が多数の推定値を変えるのを抑えます。見出しがない場合、信頼できるページ対応があればEstimated、なければUnresolvedになります。

## JSONの保存・復元

「中間結果JSONをダウンロード」から、階層・見出し・移動先・状態・根拠・候補・手動指定と目次範囲、本文先頭のページ対応を保存できます。同じPDFを読み込んでインポートすると作業を復元します。基準は任意の `page_reference` フィールド（例：`{"printed_page": "1", "pdf_page": 12}`）に保存され、このフィールドのない従来のJSONも読み込めます。SHA-256とページ数で別PDFへの誤適用を拒否します。未解決項目も保存できます。APIキー・PDFバイナリ・本文全体はJSONに含めません。**見出しは含むので、JSONも書籍に応じて適切に保管してください。**

APIを使わず、次の目次JSONだけをインポートして照合することもできます。

```json
{
  "entries": [
    {"level": 1, "title": "第1章 はじめに", "printed_page": "1"},
    {"level": 2, "title": "1.1 研究背景", "printed_page": "3"},
    {"level": 1, "title": "付録A", "printed_page": "A-1"},
    {"level": 2, "title": "追加資料", "printed_page": null}
  ]
}
```

`printed_page`は数字でも文字列にしてください。型・必須項目・空見出し・階層をPydanticで検証し、不正なLLM出力や未完了出力は結果に採用しません。

## テスト

```bash
pixi run check
# 個別に実行する場合
pixi run test
pixi run lint
pixi run format-check
# 自動整形
pixi run format
```

`check` はlint・整形チェック・通常テストをまとめて実行します。Python 3.11 / 3.13でも確認する場合は、それぞれ `pixi run -e py311 check` / `pixi run -e py313 check` を使います。CIでは同じ3環境を `--locked` で実行し、ロックファイルと依存定義のずれを検出します。

テスト時にPDFをプログラムで生成します。実際の書籍やAPIキーは不要です。単純・区間別オフセット、章扉、重複見出し、表記揺れ・軽微なOCR誤認、ローマ数字・付録、複数目次ページ、未発見項目、誤アンカー、柱・相互参照、途中開始の見出し、フィルター付き編集、JSON復元、既存アウトライン確認、出力の内容保持を検証します。Streamlit AppTestで500ページの読込→照合→生成を通します。GitHub ActionsはPython 3.11 / 3.12 / 3.13でこのテストを実行します。

API呼び出しの通常テストは偽クライアントとHTTPモックを使い、DeepSeekへの送信先・JSON出力・推論無効・送信範囲・階層検証・空の応答・APIエラーを検証します。UIの初期選択とプロバイダーごとのキー分離も確認します。**実APIテストは明示的な有効化が必要**です。

```bash
# .env または環境変数に DEEPSEEK_API_KEY を設定してから実行（API利用料が発生）
RUN_DEEPSEEK_TESTS=1 pixi run test-deepseek
```

この接続テストは人工的な日本語目次テキストと生成した目次画像を送信し、階層・見出し・印刷ページを検証します。実際のPDF本文は送りません。PowerShellでは次のように実行します。

```powershell
$env:RUN_DEEPSEEK_TESTS = "1"
pixi run test-deepseek
```

APIキー未設定、または `RUN_DEEPSEEK_TESTS=1` が未指定ならスキップします。OpenAIの任意接続テストは `RUN_OPENAI_TESTS=1 pixi run test-openai` で実行できます（`OPENAI_API_KEY` 環境変数が必要）。

### 実OCRの統合テスト（明示的に有効化）

```bash
pixi run -e ocr ocr-setup
RUN_OCR_TESTS=1 pixi run -e ocr test-ocr
# 500ページすべてを実OCRする長時間テストも含める場合
RUN_OCR_TESTS=1 RUN_OCR_LARGE_TESTS=1 pixi run -e ocr test-ocr
# 公式モデルを取得可能な環境でのみ（大型モデルをダウンロード）
RUN_OCR_TESTS=1 OCR_TEST_ENGINE=paddle pixi run -e paddle test-ocr
```

PowerShellでは ` $env:RUN_OCR_TESTS = "1" ` を設定してから実行します。通常の `pixi run test` は外部API・OCRモデル取得を行いません。生成した画像PDFにテキストがないこと、座標・信頼度・永続キャッシュの分離・失敗再処理・中断再開・500ページの画像PDFからの出力保持を偽エンジンで検証します。専用CIの `local-ocr` は小さい固定言語データを使い、Linux x86_64 / ARM・macOS ARM / Intel・Windowsで実OCRを確認します。大型Paddleモデルは `Optional OCR models` ワークフローの手動実行でのみ取得します。

### DeepSeekに接続できない場合

| 表示 | 対応 |
| --- | --- |
| HTTP 401 | DeepSeekのキーを設定したか、空白・コピー漏れがないか確認 |
| HTTP 402 | DeepSeek PlatformでAPI残高・利用枠を確認 |
| HTTP 429 | 利用上限や混雑の可能性があるため、時間を置いて再試行 |
| HTTP 400など | モデル名と公式API仕様を確認。まず `deepseek-flash` を使用 |
| 空の応答・JSON形式エラー | 目次テキストを見直して再試行。長い場合は範囲を絞る |
| 接続エラー | インターネット接続、プロキシ、`api.deepseek.com` への通信許可を確認 |

解析エラー時は既存の編集結果を保持し、不正な返答を採用しません。キーやAPIの生のエラー本文は画面・独自ログに出力しません。

## パフォーマンス・プライバシー

- テキストレイヤーは直接抽出し、本文OCR・目次送信・プレビューの必要なページだけを順に描画します。OCRテキストをPDFへ埋め込まず、出力は既存の `set_toc()` と再読込検証を利用します。
- PDFごとの抽出結果をセッションで保持し、メモリキャッシュは最大2文書／1時間、プレビューは12枚／10分です。OCR結果はSQLiteに永続化します。ブラウザ再読込時には中間JSONから編集作業を復元し、OCRはキャッシュから再開してください。
- LLMは明示的な目次解析操作時だけ呼び、編集や本文検索では呼びません。目次テキストは120,000文字までです。画像入力の費用は解像度・ページ数に依存します。
- 入力・出力PDFはメモリ上で処理し、本文画像や入力したAPIキーを独自ログ・Git・一時ファイルに保存しません。本文OCRテキストは指定したローカルキャッシュへ保存します。`.env`、PDF、仮想環境、キャッシュはGit管理外です。APIキーは選択したプロバイダーの認証に使用します。
- 同時に元PDF・出力PDF・索引を保持するため、メモリ消費はファイルサイズとテキスト量に依存します。アップロードの設定上限は1GBです。極端に大きいスキャンPDFは分割して処理してください。

## 制約・既知の問題

- 目次ページの自動検出、要約、ベクトル検索、認証、クラウド保存、共同編集は含みません。
- OCR品質や読み順に依存します。複雑な多段組、縦書き、3行を超える見出し、数式見出し、何度も同じ表題がある書籍では手動修正が必要です。テキストが存在することはOCR品質の保証ではありません。
- 本文先頭のページ対応を指定しない場合、ページ推定には同じ番号体系で複数の独立した強いアンカーが必要です。手動基準があっても、本文見出しを検出できない区間の挿入・欠落は自動検出できません。中盤・末尾の章頭でも対応を確認してください。欠落や挿入の正確な位置が分からない場合、境界区間や孤立した新オフセットでは推定を控えます。大幅なOCR誤認、複雑な番号リセット、挿入が連続する本は手動で補ってください。
- 見出し名だけでは区別できない参照や重複を完全には除外できません。Verifiedも絶対的な保証ではありません。
- DeepSeekのJSON出力はJSONの形式を指定する機能で、見出し抽出の正しさやスキーマへの適合を保証しません。Pydanticで検証しますが、抽出漏れ・見出し名・階層は確認が必要です。空白だけの返答や出力上限による未完了はエラーにします。エラー時はモデルや目次範囲を見直してください。長大な目次の自動分割・再試行結合は行いません。
- PDFは再保存されるため電子署名を維持できません。未解決項目を残したPDF生成や、既存ブックマークとの自動マージには対応しません。
- 本アプリは個人のローカル利用を想定しています。外部公開や複数人運用向けの認証・セッション保護は実装していません。
- PyMuPDFのライセンスはAGPLまたは商用ライセンスです。配布・組込み時は依存ライブラリの条件を確認してください。
