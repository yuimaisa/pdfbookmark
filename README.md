# pdfbookmark

OCR済み書籍PDFの目次をLLMで構造化し、本文見出しと照合して階層付きブックマークを生成するローカルWebアプリです。日本語UI、500〜1000ページ程度の教科書・専門書を想定しています。

## セットアップ・起動

Python **3.11以上**を使って、リポジトリのルートで実行します。

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
cp .env.example .env
# .env の OPENAI_API_KEY と OPENAI_MODEL を設定
streamlit run app.py
```

Windows PowerShellでは仮想環境を `.venv\Scripts\Activate.ps1` で有効化し、`Copy-Item .env.example .env` で設定ファイルを作成してください。利用だけの場合、依存関係のインストールは `python -m pip install -e .` でも構いません。

ブラウザで <http://127.0.0.1:8501> を開きます。初期設定はローカル接続のみです。画面左側からAPIキーとモデルを指定することもできます。初期モデルは `gpt-4.1-mini`、OpenAIの **Structured Outputs対応モデル**が必要です。APIの利用料が発生します。

APIキーなしでも「500ページのサンプルPDFで試す」→「サンプル目次を読み込む（API不要）」から、照合・編集・PDF生成を試せます。サンプルの目次は英語ですが、アプリと見出し照合は日本語にも対応します。

## 使い方

1. OCR済みPDFを読み込みます。ページ数、テキストを含むページ数、既存のブックマーク数を表示します。テキストレイヤーがないPDFやパスワード保護されたPDFは利用できません。
2. 目次の開始・終了PDFページを指定し、「この範囲の目次テキストを抽出」を押します。必要に応じてプレビューし、抽出テキストを修正します。**画面上のPDFページ番号はすべて1始まり**です。
3. 「LLMで目次を解析」を押します。送信対象はこの目次テキストだけです。目次を変更した場合は再度解析します。解析・目次JSON読込は既存の編集結果を置き換えます。
4. 「自動ページ照合を実行」を押します。本文テキストをローカル検索し、根拠・候補・ページ対応区間・不連続を表示します。ページ移動や編集ではAPI呼び出し・全文抽出・再照合を行いません。
5. 結果を表で編集し、**「編集内容を保存」**を押します。階層、見出し、印刷ページ、PDFページを変更でき、末尾で追加、行選択で削除できます。「未解決のみ」「要確認のみ」の絞り込み中も、他の行は保持されます。追加行は末尾に入ります。
6. 各項目の根拠・候補と対象ページのプレビューを確認します。PDFページを変更した項目は手動指定として保持され、再照合時に保持するか選べます。自動判定された見出し・印刷ページを変更すると移動先を解除するので、再照合または手動指定してください。
7. 未解決項目を修正・削除し、「ブックマーク付きPDFを生成」を押してダウンロードします。既存ブックマークがある場合、出力側で置き換えるチェックが必要です。保存後にPDFを開き直し、全項目の数・階層・移動先を検証します。

階層は1から始め、深くするときは1段ずつ指定します。同じPDFページに複数項目を置けます。自動結果がすべて確定していれば、そのままPDFを生成できます。元のPDFのバイト列、ページ内容、画像は変更しません。出力には元のPDFが保持する注釈・メタデータも含まれます。

## 検証状態と照合方法

| 状態 | 根拠 | 確認の目安 |
| --- | --- | --- |
| Verified | 独立した本文見出しの完全一致・正規化一致などが強く、重複や順序矛盾がない | 必要に応じてプレビュー |
| Probable | 曖昧一致・重複候補がページ対応と整合、またはユーザーの手動指定 | プレビューを推奨 |
| Estimated | 複数のアンカーによるページ対応のみで推定 | 本文見出しの裏付けはないため要確認 |
| Unresolved | 根拠不足、重複、順序矛盾、オフセット変化の境界など | 手動指定または削除が必要 |

信頼度は確率ではなく、照合方法に基づくスコアです。手動指定は本文検証の完了を意味しないため、Verifiedにはしません。

処理は次の2段階です。

- **見出し検索**：全ページのテキスト・行／ブロック位置・文字サイズを一度抽出。NFKC、空白・記号・章節番号を検索用に正規化し、原文を保持します。文字n-gram索引で候補を絞り、完全一致・本文一致・RapidFuzzの曖昧一致、章節番号、ページ内の位置、文字サイズを評価します。最大3行の折返し見出しに対応します。指定した目次ページを除外し、繰返しの柱・フッター、参照表現や目次らしい行を減点します。
- **ページ対応**：高信頼度・重複なしの見出しから目次順に単調なアンカー列を選び、アラビア数字・ローマ数字・付録番号を別体系として扱います。異なる印刷ページのアンカーが少なくとも2件、同じオフセットを支持した場合だけ推定に使います。区間ごとに異なるオフセットを認め、切替位置が未確定の区間では数値だけの推定を避けます。強い本文一致は暫定オフセットより優先します。

この設計により、単一の誤一致が多数の推定値を変えるのを抑えます。見出しがない場合、信頼できるページ対応があればEstimated、なければUnresolvedになります。

## JSONの保存・復元

「中間結果JSONをダウンロード」から、階層・見出し・移動先・状態・根拠・候補・手動指定と目次範囲を保存できます。同じPDFを読み込んでインポートすると作業を復元します。SHA-256とページ数で別PDFへの誤適用を拒否します。未解決項目も保存できます。APIキー・PDFバイナリ・本文全体はJSONに含めません。**見出しは含むので、JSONも書籍に応じて適切に保管してください。**

APIを使わず、次の目次JSONだけをインポートして照合することもできます。

```json
{
  "entries": [
    {"level": 1, "title": "第1章 はじめに", "printed_page": "1"},
    {"level": 2, "title": "1.1 研究背景", "printed_page": "3"},
    {"level": 1, "title": "付録A", "printed_page": "A-1"},
    {"level": 2, "title": "追加資料", "printed_page": null}
  ]
}
```

`printed_page`は数字でも文字列にしてください。型・必須項目・空見出し・階層をPydanticで検証し、不正なLLM出力や未完了出力は結果に採用しません。

## テスト

```bash
pytest -m 'not integration'
ruff check .
ruff format --check .
```

テスト時にPDFをプログラムで生成します。実際の書籍やAPIキーは不要です。単純・区間別オフセット、章扉、重複見出し、表記揺れ・軽微なOCR誤認、ローマ数字・付録、複数目次ページ、未発見項目、誤アンカー、柱・相互参照、途中開始の見出し、フィルター付き編集、JSON復元、既存アウトライン確認、出力の内容保持を検証します。Streamlit AppTestで500ページの読込→照合→生成を通します。GitHub ActionsはPython 3.11 / 3.12 / 3.13でこのテストを実行します。

OpenAI呼び出しの通常テストは偽クライアントを使い、送信範囲・スキーマ・階層・失敗時の挙動を検証します。**実APIテストは明示的な有効化が必要**です。

```bash
# OPENAI_API_KEYを環境変数として設定してから実行（API利用料が発生）
RUN_OPENAI_TESTS=1 pytest -m integration
```

## 構成

```text
app.py                        日本語Streamlit UI・セッション・メモリキャッシュ
pdfbookmark/pdf.py            PDF抽出・位置情報・オンデマンドプレビュー
pdfbookmark/llm.py            TocParserプロトコル・OpenAI Structured Outputs
pdfbookmark/models.py         目次・結果・中間JSONの検証
pdfbookmark/normalization.py   検索用正規化・番号体系
pdfbookmark/matching.py        見出し索引・段階的照合・区間別オフセット
pdfbookmark/editing.py         絞り込み結果の安全な編集・マージ
pdfbookmark/export.py          PDF生成・再検証・JSON保存復元
pdfbookmark/demo.py            人工的な500ページ書籍
tests/                        生成PDF・LLMモック・UI・任意の実APIテスト
```

LLMは `TocParser.parse(text) -> TocDocument` を実装して差し替えられます。初期UIはOpenAIのみです。将来のOCRは `pdf.py` の抽出層を拡張できます。

## パフォーマンス・プライバシー

- 全ページの画像化はせず、テキストレイヤーを直接抽出します。プレビューは要求された1ページのみを描画します。
- PDFごとの抽出結果をセッションで保持し、メモリキャッシュは最大2文書／1時間、プレビューは12枚／10分です。ディスク永続化はしません。ブラウザ再読込時には中間JSONから作業を復元してください。
- LLMは明示的な目次解析操作時だけ呼び、編集や本文検索では呼びません。目次テキストは120,000文字までです。
- 入力・出力PDFはメモリ上で処理し、PDF本文やAPIキーを独自ログ・Git・一時ファイルに保存しません。`.env`、PDF、仮想環境、キャッシュはGit管理外です。APIキーはOpenAIの認証にだけ使用します。
- 同時に元PDF・出力PDF・索引を保持するため、メモリ消費はファイルサイズとテキスト量に依存します。アップロードの設定上限は1GBです。極端に大きいスキャンPDFは分割して処理してください。

## 制約・既知の問題

- OCR、画像からの文字認識、目次自動検出、要約、ベクトル検索、認証、クラウド保存、共同編集は含みません。
- OCR品質や読み順に依存します。複雑な多段組、縦書き、3行を超える見出し、数式見出し、何度も同じ表題がある書籍では手動修正が必要です。テキストが存在することはOCR品質の保証ではありません。
- ページ対応には同じ番号体系で複数の独立した強いアンカーが必要です。欠落や挿入の正確な位置が分からない場合、境界区間や孤立した新オフセットでは推定を控えます。大幅なOCR誤認、複雑な番号リセット、挿入が連続する本は手動で補ってください。
- 見出し名だけでは区別できない参照や重複を完全には除外できません。Verifiedも絶対的な保証ではありません。
- モデルによってStructured Outputs未対応や出力上限の差があります。エラー時はモデルや目次範囲を見直してください。長大な目次の自動分割・再試行結合は行いません。
- PDFは再保存されるため電子署名を維持できません。未解決項目を残したPDF生成や、既存ブックマークとの自動マージには対応しません。
- 本アプリは個人のローカル利用を想定しています。外部公開や複数人運用向けの認証・セッション保護は実装していません。
